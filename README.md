# AzureKiln Backup

[简体中文](README.md) | [English](README.en.md) | [繁體中文](README.zh-TW.md)

AzureKiln Backup 是面向单一管理员的目录与 Vaultwarden 备份管理系统。系统通过 rclone 管理远端备份，提供定时执行、加密归档、版本保留、邮件通知，以及备份执行和临时空间的可视化管理。可选用 AzureKiln OAuth2/OIDC 登录。

## 功能范围

| 模块 | 能力 |
| --- | --- |
| 备份来源 | 指定目录或单个文件；Vaultwarden SQLite、PostgreSQL、MySQL/MariaDB；new-api 全量数据；系统配置 |
| 站点管理 | 站点名称、多个域名/HTTP(S) 地址、独立标签与备注、GitHub/CNB/Gitee/GitCode 仓库链接；与备份任务双向多对多关联 |
| 归档与远端 | tar.gz、AES-256 加密的 7z/ZIP；rclone 多目标上传、远端校验与版本保留 |
| 调度与通知 | 定时或手动执行；开始、成功和失败邮件；独立记录备份与通知结果 |
| 运维管理 | 执行历史、归档下载、只读源文件浏览、临时空间统计及本地归档清理 |

## 运行要求

本地运行需要 Node.js 24 或更新版本。目录归档需要 tar；7z 和 ZIP 归档需要 7-Zip；远端传输需要 rclone。Vaultwarden 的 SQLite 备份使用 Node.js 内置在线备份接口；PostgreSQL 和 MySQL/MariaDB 分别需要相应的数据库客户端。缺少工具时，管理界面会显示实际状态，不会生成模拟备份。可通过 `RCLONE_BINARY`、`SEVEN_ZIP_BINARY`、`PG_DUMP_BINARY`、`MYSQL_DUMP_BINARY` 指定可执行文件路径。

## 本地部署

```powershell
npm install
npm run dev
```

开发入口默认 `http://127.0.0.1:5173`，API 默认 `16323`；端口被占用时开发脚本会选择空闲端口。第一次打开页面创建管理员。配置和数据库保存在 `.data/`，默认允许备份的源目录为 `sources/`。通过 `.env` 设置 `SOURCE_ROOTS` 扩大允许范围，Windows 多目录用分号分隔，Linux 用冒号分隔。

```powershell
npm run check
npm test
npm run build
npm start
```

构建后的前端由 API 服务直接提供，默认生产入口 `http://127.0.0.1:16323`。本地设置见 `.env.example`。

## Docker 部署

使用 `.env.docker.example` 对应的变量配置 `.env`，填写私密的 `SETUP_TOKEN` 或初始管理员账号密码。按实际域名设置 `BACKUP_PUBLIC_URL`，修改 `compose.yaml` 中 `/sources` 下的目录挂载及现有 rclone 配置挂载。`/sources` 是容器内的备份源目录入口，宿主机路径可按需映射到它的子目录；`/data` 保存本应用的状态，两者不能重叠。登录后“文件管理”页面会列出 `SOURCE_ROOTS` 允许范围内的容器目录与文件。该页面只读，可从目录直接新建备份任务。

```shell
docker compose up -d --build
```

示例 Compose 只把端口发布到宿主机 `127.0.0.1:16323`，由 Nginx/宝塔反向代理提供 HTTPS。容器以 root 运行，源目录保持只读挂载。无需 Docker socket。

现有 rclone 配置目录通过 `RCLONE_CONFIG_DIR` 只读挂载到 `/config`，然后在“存储”页面从 `/config/rclone.conf` 导入。实际运行配置会保存到持久卷中的私有目录，可写入刷新后的 OAuth token。重新导入是明确操作，不会定期覆盖已经刷新的 token。

容器以 root 运行，可以读取仅 root 可访问的 rclone 配置。导入后的运行配置保存在 `/data/rclone/`，原配置挂载保持只读。

## 文件管理

登录后打开“文件管理”。只有一个允许的根目录时自动进入；多个根目录时先显示目录列表。支持面包屑、上一级、当前目录名称搜索（不区分大小写）、每页 100 项、刷新，以及文件大小和修改时间。目录排在文件之前；搜索覆盖当前目录全部条目，不递归搜索子目录。点击目录旁的加号或“备份此目录”，可将路径带入新任务。

例如，在 `compose.yaml` 的 `volumes` 下添加实际宿主机目录：

```yaml
- /www/wwwroot:/sources/websites:ro
- /srv/vaultwarden:/sources/vaultwarden:ro
```

`.env` 中使用 `SOURCE_ROOTS=/sources` 时，页面会显示 `websites` 和 `vaultwarden`。如果只允许单独访问这两个目录，可设置 `SOURCE_ROOTS='["/sources/websites","/sources/vaultwarden"]'`。页面使用容器内路径；修改配置后运行 `docker compose up -d` 使挂载和环境变量生效。

页面为空时检查挂载是否已启用、容器路径是否包含在 `SOURCE_ROOTS` 中，以及容器是否能读取文件并进入目录。符号链接不会展示或跟随。目录暂时不可用时会显示错误，恢复挂载或权限后点击“重试”。

## 任务行为

任务可以打标签（最多 10 个，例如 `mysql`、`生产`），任务列表可按标签筛选，点击任务下的标签也会筛选，搜索同样匹配标签。

新建目录任务时勾选“批量添加”，源目录改为选择父目录，页面列出其下的子目录，勾选后一次创建多个任务，其余设置全部相同。任务名按模板生成（`{folder}` 替换为子目录名），每个远端目标上传到“保存目录/子目录名”。例如父目录 `/sources/mysql` 下有 `blog_azurekiln_cn`、`azurekiln_cn`，保存目录为 `backups/mysql`，就会生成两个任务，分别上传到 `backups/mysql/blog_azurekiln_cn` 和 `backups/mysql/azurekiln_cn`。已有任务的子目录不可勾选；任一子目录校验失败时整批都不创建。创建后各任务互相独立，修改需逐个编辑。批量添加会自动把父目录名填成标签，方便这些任务在列表里聚成一组，可在保存前修改或删除。

新建任务时还可以选择“单文件”类型：在编辑器中通过“浏览源文件”点选一个常规文件（文件管理页的“备份此文件”也可直接对文件发起任务），执行时只打包该文件本身，按原文件名保存，并保留其字节与元数据，不会带上同级目录的其它文件。单文件任务支持手动和定时执行，沿用同样的压缩/加密、上传校验、版本保留、取消与临时文件清理；目录监听、增量备份和排除规则不适用于单文件。源文件必须位于已配置的源目录内，符号链接和特殊文件（设备、管道、套接字等）不能作为源，也不会读取应用状态目录。单文件备份保存的是文件执行当时的原始内容；需要一致性快照的运行中数据库，应改用对应的数据库或 new-api 任务类型导出。

任务列表和任务详情提供“复制任务”操作：服务端复制该任务的配置、已加密保存的归档与数据库密钥、目标以及站点关联，生成具有全新 ID、名称和时间戳的副本。副本默认处于暂停状态，计划与监听配置会保留但不生效，直到手动启用；执行历史、队列状态、下次执行时间和监听基线都不会复制，因此副本的历史为空。固定不可删除的“系统配置”任务不能复制。原任务正在执行时也可以复制，此后两者互不影响，修改或删除其中一个都不会改变另一个。复制成功后页面会打开这个暂停的副本编辑器，无需重新填写密钥；响应不会返回任何密钥明文，复制失败时列表里也不会出现空记录。

任务列表可按“标签”“类型”或“源父目录”分组，也可以不分组。分组标题显示名称、任务数量和失败数量，点击标题即可折叠或展开，工具栏里的“全部折叠”“全部展开”一次处理所有分组。折叠状态和分组方式会被记住，刷新后保持原样；搜索时所有分组自动展开，避免命中的任务藏在折叠的分组里。分组与搜索、启用状态筛选、标签筛选同时生效，各分组的数量按筛选后的结果显示。

目录任务可在“计划与通知”中启用文件变化监听。监听默认关闭，递归覆盖所选目录；文件变化经过可设置的 1–300 秒合并时间（默认 5 秒）后，创建一次完整备份版本。备份期间发生的新变化会在当前执行结束后再触发一次。排除规则适用于监听触发。任务暂停、删除或关闭监听后，不再监听该目录；Vaultwarden 和系统配置任务不支持此选项。任务详情显示监听状态和错误。

文件监听依赖操作系统的文件事件。网络文件系统、部分容器挂载和短暂断开的目录可能漏报事件；服务会定期尝试重新连接监听，但不能补回所有断线期间的变化。重要数据建议同时启用定时执行。频繁修改的大目录应适当延长合并时间。任务列表的“文件监听”开关可直接开关监听，并保留监听方式和合并时间。

监听方式有两种。“整个目录”每次变化都完整归档并上传。“仅新增和修改的文件”在开启时将现有文件记录为基线（按路径、大小和修改时间），之后的监听执行只打包新增或修改的文件，生成 `任务名.incremental.7z` 一类的增量版本；归档内的 `incremental.*.tar` 包含这些文件，`changes.*.json` 列出新增、修改和删除的路径。没有新增或修改时，执行直接成功，不上传也不发送邮件；仅有删除时，删除记录在下一个增量版本中。手动和定时执行始终是完整备份，并将基线重置为当前目录。服务重启后会对照基线补备份停机期间的变化。还原时先解压最近的完整版本，再按时间顺序解压其后的增量版本，并按 `changes.*.json` 删除文件。保留策略的版本数和天数只计算完整版本；增量版本早于最早保留的完整版本时才被清理，因此建议配合定时完整备份。只比较大小和修改时间，内容改变但两者都不变的文件不会被识别。

普通目录任务先创建保留文件元数据的 tar，再按所选格式压缩。加密使用 7z 或 ZIP 的 AES-256；7z 同时加密文件名。未加密任务可使用 tar.gz。任务编辑器可为 7z 选择 LZMA2 或 LZMA 算法，并设置 1–8 个压缩线程及 8–256 MiB 字典。线程和字典的“自动”档在压缩级别 7–9 时分别使用 1 线程和 32 MiB 字典，以降低低内存服务器上的换页风险；低级别则交由 7z 决定。更大的字典通常会增加内存占用。ZIP 使用 Deflate，tar.gz 使用 gzip，这两种格式不应用 7z 算法和字典设置。

“版本文件夹名”和“压缩包文件名”可在任务的压缩设置中配置，支持 `{datetime}`（UTC 时间）和 `{task}`（任务名）；文件夹名必须包含 `{datetime}`，压缩包扩展名由格式自动添加。默认远端布局为 `保存目录/2026-09-28_11-24-18-123Z/任务名.7z`，同目录的 `complete.json` 记录任务 ID、执行 ID、大小与 SHA-256。已有备份仍按原路径下载和清理，请勿手工移动或改名。

排除规则支持路径文字、`*` 和 `?`，例如 `*.log`、`cache/**`；扩展 glob 语法不接受，以保证目录检查与归档工具的行为一致。

Vaultwarden 专用任务包含 SQLite、PostgreSQL、MySQL/MariaDB 三种模式，默认 SQLite，页面按类型显示数据库连接和 TLS 字段。它生成数据库一致性快照/导出，并收集存在的 `config.json`、`rsa_key*`、`attachments`、`sends`，支持自定义路径。数据库失败则任务失败；可选内容不存在会记录为跳过。归档内保留上游的 `db.*`、`config.*`、`rsakey.*`、`attachments.*`、`sends.*` 结构。

new-api 专用任务用于把 new-api 的整套持久化数据搬到另一台机器还原（不含程序源码和 Docker 镜像）。它导出主库（SQLite 在线快照、MySQL `--single-transaction`、PostgreSQL `pg_dump`）与可选的独立日志库（`LOG_SQL_DSN`；ClickHouse 只写入手工导出命令并记录告警），收集必需的 `.env` 以及可选的 `docker-compose.yml`、systemd unit、反代配置、插件脚本目录，并打包数据目录（自动排除 `new-api-body-cache`、`*.db-wal`、`*.db-shm`）。归档内的 `manifest.json` 记录主库/日志库引擎与库名、逐表行数与内容哈希、文件哈希、new-api 版本和告警；`RESTORE.md` 给出逐步还原与逐表校验命令。`包含 logs 表` 可关闭，此时消耗与 tokens 历史会缺失并在归档中标注。该类型强制使用 AES-256 加密的 7z 归档，因为 `.env` 内的 `CRYPTO_SECRET` 是解密渠道密钥的唯一钥匙，还原时必须原样保留。

上传使用 rclone copy/copyto，每次执行均生成独立的远端版本。明文临时数据在归档验证后清理。上传验证成功后，本地归档按“系统设置 → 临时文件”中的策略处理：默认立即清理；选择手动清理时，归档保留在应用临时目录，直至管理员在该页面逐份或全部清理。邮件失败不改变备份成功状态，也不阻止归档策略执行。失败临时数据受每任务最新一次、保留时间和总空间上限约束。远端过期删除仅作用于该任务记录的成功备份版本。

设置页显示临时文件总占用、手动保留的成功归档占用、其他临时文件占用和已保留归档列表。手动保留的成功归档计入临时空间上限，不受失败文件的自动清扫规则影响；容量不足时，新备份会失败，需要先清理本地归档或提高上限。切换回“立即清理”只影响后续成功备份，不会自动删除此前手动保留的归档。

手动保留未加密的 tar.gz 归档时，本地副本同样未加密。应限制对应用持久目录的访问，并在不再需要本地副本后及时清理。

临时空间通过预检查、下载预留和每 250 毫秒的检查控制；导出或压缩触及上限时会中止并清理明文。检查间隔内仍可能短暂超额，应为大型任务预留足够磁盘空间。服务重启会清理中断任务遗留的明文和数据库凭据。

## 站点管理

“站点管理”用于把现有备份任务按站点归档，不改变任务的执行方式。站点包含名称、一个或多个域名/HTTP(S) 访问地址、独立标签、可选备注，以及关联的备份任务；服务端另行记录创建和更新时间。每个站点还可以绑定多个代码仓库链接。

站点列表采用紧凑的行布局，首行是站点名称与第一个访问地址。访问地址只显示主机名（不含协议、端口、路径、查询和片段），点击时仍打开保存的完整 URL；其余已保存的地址只在编辑器中显示，不会被丢弃或改写。地址是透明的文字链接，与填充式的标签筛选按钮区分开；没有地址的站点显示占位文字而不是链接。备注是可选的纯文本（最多 500 字，可换行），列表仅在非空时显示一行预览，完整内容在编辑器中查看；系统始终按纯文本显示，不解析 HTML。

域名可填写裸域名或 `http(s)://` 地址，裸域名按 HTTPS 处理；最多 20 条，每条不超过 2048 字符，地址中不能包含用户名或密码。域名和关联任务都允许先留空，之后再逐步补充。域名只是清单与跳转信息，系统不会在保存时探测或访问这些地址；只有校验通过的 HTTP(S) 链接才可点击打开。

代码仓库用于记录站点的源码地址并支持一键跳转。每个站点最多 20 条，每条不超过 2048 字符，支持 GitHub、CNB、Gitee 和 GitCode（含 `hub.gitcode.com`）的仓库页面；地址必须包含仓库路径（如 `owner/repo`），保留路径、查询和片段的大小写，裸主机名按 HTTPS 处理，显式填写的 `http://` 会原样保留。同一站点可以绑定同一平台上的多个仓库（例如前端与后端、镜像仓库），列表用小图标配合可区分的仓库名显示，键盘和读屏也能识别。平台按完整主机名识别，不做子串猜测；系统不会访问、克隆或校验仓库是否存在，不需要账号或令牌，图标随应用本地打包，不依赖网络。无法识别的站点、含用户名或密码、非 HTTP(S) 协议、非默认端口、反斜杠或控制字符的地址会被拒绝；完全相同的规范化链接只保留第一次出现。仓库可以先留空，清空仓库列表不会影响地址、备注、标签或任务关联。

站点标签与任务标签各自独立，互不复制或修改。站点与任务是多对多关系：一个站点可以关联数据库、配置、文件等多个任务，同一个任务（例如共享数据库）也可以被多个站点关联。解绑或删除站点只移除站点记录及其关联，备份任务、计划、监听、凭据、执行历史、本地/远端归档以及其他站点的关联都保持不变；删除任务会移除它在所有站点中的关联，但仍遵循现有的任务删除保护与历史保留规则。

站点列表支持按名称、域名、标签、仓库地址或备注搜索，并可按站点标签筛选；列表直接显示站点名称、首个访问地址、仓库图标、备注预览、站点标签，以及已关联任务的名称、类型与当前运行状态，点击任务名称打开原有任务详情。任务详情同时显示当前关联的站点。列表中的状态只反映该关联任务最近一次执行，不表示整个站点可以完整恢复。

“备份概览”页的主面板显示站点列表（按保存顺序最多 6 个），并给出站点总数和“全部站点”入口；没有站点时提供新增站点的入口。概览的统计、当前执行、运行环境和最近执行保持不变；站点与任务独立加载，概览读取失败不会隐藏已成功读取的站点，任务列表读取失败也不会把已保存的关联显示成“未关联”。

站点数据与其他状态一起保存在 `state.sqlite` 中，因此会随“系统配置”备份一并导出，并在导入时恢复站点及其关联，包括仓库、备注与地址顺序；导入不含站点表的旧归档时，站点列表为空，原有任务不受影响。

## 授权登录与邮件

在 AzureKiln OAuth2 创建机密客户端，回调地址为 `BACKUP_PUBLIC_URL` 加 `/api/auth/oidc/callback`。填写 issuer、Client ID、Client Secret 和允许登录的管理员 `sub`。系统使用授权码、PKCE、state、nonce 和 ID Token 校验，OAuth 身份映射到同一个管理员。

邮件设置支持 STARTTLS、TLS 和无加密连接、发件人、多个收件人及测试邮件。任务可独立选择开始、成功和失败通知。通知状态与备份状态分别记录。

MySQL/MariaDB 的“要求 TLS”同时验证服务端证书，需有效的信任链或配置 CA；连接失败时不会降级为明文。

## 恢复与配置保管

从任务版本列表下载归档，使用对应历史密码解密。普通目录解压内层 tar；Vaultwarden 归档按数据库类型恢复 `db.*`，并恢复配置、RSA、附件和 Sends。恢复覆盖原数据前停止 Vaultwarden，并先在独立目录/数据库验证归档。PostgreSQL 的 pg_dump 客户端不能比服务器主版本更旧；部署时核对镜像客户端版本，必要时提供匹配版本的可执行文件。

数据库在线快照保证数据库自身一致性，附件在备份期间发生变化时不保证全局同一时刻的状态。严格一致性需要维护窗口。Vaultwarden `.env` 和 Compose 文件在数据目录之外时，应建立额外目录任务。

配置中的密码使用独立密钥加密保存。请保护并备份持久数据及 `.data/secret.key`（容器位于 `/data`）；丢失密钥后无法恢复保存的凭据。轮换压缩密码只影响新版本，历史包仍需原密码。完成一次实际恢复验证后，再移除旧的 `vaultwarden-backup` 容器。

普通 rclone 配置导入后自动使用 rclone 原生格式加密，生成的配置密码也加密保存；原配置文件不会被修改。导入已有加密配置时填写其密码，验证失败不会替换运行中的配置及密码。

## 系统配置备份与导入

“系统配置”是内置任务，初始为停用状态。编辑它，添加 rclone 目标、设置 7z 压缩包密码，并按需启用定时计划。执行时会对 `state.sqlite` 做在线快照，同时打包 `secret.key`、正在使用的 `rclone.conf`，以及容器可读取的部署 `.env` 和 `compose.yaml`。普通任务和系统任务都可以填写描述。系统归档强制采用 7z AES-256 加密；完成后可在该任务的“备份版本”中下载导出包。请单独保管压缩包密码。

Compose 将宿主机 `.env` 和 `compose.yaml` 只读挂载到 `/system-config/`。其他部署方式可设置 `SYSTEM_ENV_FILE`、`SYSTEM_COMPOSE_FILE` 为容器内可读取的文件路径；未指定时仅在工作目录存在对应文件时纳入归档。源目录的数据和反向代理配置不在归档中。

导入时，先用当前管理员账号登录，打开“系统配置”任务并选择“导入配置”，上传该任务导出的 7z 包和密码。上传包上限为 256 MiB，解压后的配置上限为 2 GiB。服务会验证归档、文件摘要、SQLite 完整性和加密密钥，暂存到 `/data/system-restore-pending`；执行 `docker compose restart backup` 后才替换当前任务、设置、管理员账号和运行中的 rclone 配置。替换前的状态保存在 `/data/system-restore-previous-*`；若替换中断，下次启动会先恢复原配置，再重试待导入归档。导入后的备份版本会在打开“备份版本”时根据远端完成记录补认，远端暂时不可用时可稍后重试。归档中的部署文件另存为 `/data/restored-deployment.env`、`/data/restored-compose.yaml`，需要在宿主机人工核对并应用；只读挂载不会被自动覆盖。使用外部 `BACKUP_MASTER_KEY` 时，重启前必须将该环境变量改为归档对应的密钥；暂存目录中的 `deployment.env` 可供核对。
